EXERCISE TRACKER — ARCHITECTURE (the truth doc for this project)
=====================================================================================
A single-page gym tracker. It logs sets per exercise and shows, by colour and elapsed
time, what was trained recently and what is overdue. All data lives in the browser's
localStorage. There is no server.

Craft standard: /media/sf_claude.code/ENGINEERING.craft-bar.txt
Shared direction: /media/sf_claude.code/WORLD.shared-direction.txt


FILES
-------------------------------------------------------------------------------------
exercise.tracker.html ... The app. All new work happens here and in files it loads.
exercise.tracker.css .... All visual styling. Row colours are the exception: they carry
                          meaning, so the scripts set them inline.
scripts/workout-time-limits.js ... The time spans workout decisions are built on.
scripts/exercise-names.js ........ The fixed exercise list. Replaced by user-managed
                                   exercises later.
scripts/clock.js ................. The only place the app reads the system clock.
scripts/elapsed-time-text.js ..... Turns seconds into on-screen text such as 2.5h.
scripts/exercise-row-colours.js .. Picks a row's colour from set count and age.
scripts/workout-rules.js ......... Decides same workout, new workout, or ask, and rolls
                                   an exercise into its previous-workout state.
scripts/exercise-list-display.js . Sorts and draws the main exercise list.
scripts/exercise-dialogs.js ...... Shows and hides the two dialogs.
scripts/button-press-handlers.js . What each button and row does on press and release.
scripts/header-times-display.js .. Writes the clock and workout time at the top.
scripts/app-start.js ............. Starts the app on load and sets up the refresh timers.
index2.html ............. Reference only. A browser "Save As" snapshot of the live page.
                          NEVER edited. Its visible dialog state is a snapshot artifact.
index.html .............. Disregarded. Not part of this project.


HOW WE WORK
-------------------------------------------------------------------------------------
- Very tiny steps. The owner runs every change live before the next one starts.
- This session runs in a VM. The owner tests on the VM's host, through the shared folder.
- No git. Craft rule 7.8's "commit between steps" does not apply here. Steps stay small
  enough to undo by hand instead.
- Posture: AGGRESSIVE on structure (standing order 1). The owner's real data is on their
  phone and nothing here reaches it until the owner uploads.


WHERE THE REAL DATA IS
-------------------------------------------------------------------------------------
The live app is used only on the owner's phone. Browsers separate stored data by exact
address, including http versus https.

- A page opened from the shared folder has its own empty data. Testing there is safe.
- The revised app will be hosted on render.com, a different address from index2.html's
  site. The two will NOT share data, and that separation is the owner's intent. The new
  app starts empty there, and the owner moves over manually.
- So the storage format is free to change. Nothing here has to stay compatible with
  index2.html's stored data.


PROJECT LAWS
-------------------------------------------------------------------------------------
1. EVERY USER CHOICE IS SAVED THE MOMENT IT IS MADE. The owner's words: "i can not control
   when a user will kill the browser (on phone)". Add, Del, New, Same, and later creating,
   renaming and deleting an exercise all write to localStorage immediately, in the same
   handler. Nothing waits for a later save, a timer, or the page closing. Stored data is
   the only truth, and no copy of it is kept in memory between actions. Any future storage
   layer must write through. Pinned by tests/saved-immediately.test.mjs. Every new user
   action gets a test there.


TESTS
-------------------------------------------------------------------------------------
Run from the project folder (Node only, nothing to install):

    node --test

tests/load-app-in-fake-page.mjs runs the real scripts and real button attributes against a
fake clock, storage and page. It cannot show layout, so the owner's host test still matters.


PINNED QUESTIONS (decided later, not forgotten)
-------------------------------------------------------------------------------------
- RENDER ROOT ADDRESS. Render serves index.html at the site root. The app is
  exercise.tracker.html, so it needs either the full path in the address or a Render
  rewrite rule. Must be decided at the Render deploy step.


DECISIONS
-------------------------------------------------------------------------------------
- Plain <script src> tags, not JavaScript modules. The existing code relies on implicit
  globals and inline onmousedown handlers, which modules would break, and modules do not
  load from a double-clicked file. Moving to modules would be its own later step.


LAYERS
-------------------------------------------------------------------------------------
A file may only depend on the layers below it (craft rule 3.1). Plain script tags have no
imports, so the tag order in exercise.tracker.html states this order. Top of this list is
the highest layer and loads last.

5. Start ......... app-start
4. Input ......... button-press-handlers
3. Screen ........ exercise-list-display, exercise-dialogs, header-times-display
2. Decisions ..... workout-rules, exercise-row-colours, elapsed-time-text
1. Foundations ... workout-time-limits, exercise-names, clock

Known seam erosion (craft rule 3.3): localStorage is read and written directly across
layers 2, 3 and 4. A single stored-exercise layer belongs here before permanent exercise
ids are built, because that change would otherwise touch every one of those files.
